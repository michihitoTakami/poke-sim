# 終局を優先する時間制限付き探索

`--planner on --value-run runs/terminal-value-v2`の既定は、1判断に8.5秒の予算を持つ木探索。
固定3ターンの打ち切りだけで選ばない。API・ラダーとも同じAdvisorを使う。
重みの再学習は不要で、v2のモデルを途中評価として再利用する。

## 修正した問題

実ログの2026-10-16 05:22終了対戦の14ターン目では、相手の最後のドラパルトがHP1%。
フラエッテのムーンフォースで倒せる対面で瞑想を選んでいた。
旧探索は「今勝つ」「瞑想してから勝つ」を両方+1とし、同点を解消しなかった。
この局面の観測済みprefixと仮説世界を回帰fixtureとして保存した。将来のログは入力しない。

新探索の実装中には、RPCの時間境界で試行を切り、途中評価を混ぜると0.0001程度の差で
再び瞑想を選ぶ問題も再現した。各試行をgeneratorで保持し、次のRPCで続きから進める。
最終期限に残った1試行は未完了として破棄する。勝ち・負け・学習価値に置き換えない。

## 手の比較

1. 同じ公開観測では、同じ乱数seedで相手の型の仮説を生成する。後知恵で相手の型を確定しない。
2. 相手が最後の1体なら、攻撃による即勝ちを先に確認する。
   各仮説世界・全合法応答・エンジンの離散乱数分岐を列挙できた場合だけ確認済みとする。
   予算超過、列挙上限、未対応の乱数、まもる等の逃げ道は確認成功としない。
   これは仮説世界内の確認であり、未公開の全ての型への数学的保証ではない。
3. 即勝ちを確認できなければ、全root手×相手の全合法応答をまず1回ずつ実行して途中価値を得る。
   相手の積み・回復・状態異常・交代も除外しない。
4. 残り時間で情報集合を共有するUCT木探索を行う。後続の判断も木の統計から選び直す。
   1回の試行で新しい枝を開いた後は、本人`expert`、相手`tactical/disrupt`の公開参照方策で終局を目指す。
   木の方策も参照方策も、その本人のrequestと公開履歴だけを受け取る。
   自分の観測が同じなら隠れた相手の持ち物が違っても同じ木ノードを使う。
5. 各試行の上限は120通常ターン。上限まで未決着なら、通常の技選択局面でV_refを補助評価に使う。
   最終時刻による未完了、上限による途中評価、実際の終局、実行エラーは別々に記録する。
6. 相手の型をまたいで1つの判断を選ぶ。既存の予測と最悪応答への備え`rho=0.3`を使う。
   決定的に1手を使う既定運用では、各手そのものの期待値と最悪値で比較する。
   混合戦略の確率が最大の手だけを採用し、その混合戦略全体の安全性があると見なすことはしない。
   `--sample`では、混合戦略を実際にサンプリングする。
7. 勝敗の目的値が同じ手の間だけ、終局の速さを第2目的にする。
   HP差や速度への報酬で勝率を下げる手を上位にしない。

強制交代も、全候補を1つの探索要求で比較して同じ予算を共有する。
通常の3対3・未公開情報・乱数を含む全ゲームを、常に10秒で完全解析する保証はない。
終局試行が増えても、参照方策の弱さや仮説世界の誤りは残る。
「終局まで試行した件数」は、「最善応答を全て終局まで証明した件数」ではない。

## 起動と確認

```bash
PLANNER=on EXTRA="--value-run runs/terminal-value-v2" \
  setsid nohup ./scripts/collect.sh > /dev/null 2>&1 < /dev/null &
```

予算の変更例は`EXTRA='--value-run runs/terminal-value-v2 --search {"decisionMs":8500}'`。
`decisionMs`は100〜9000ms。既定8500msからRPC終了・推論・最終の手の比較に余裕を残し、
実測で1判断10秒以内か確認する。ワーカー全体が停止した場合は既存のタイムアウトで再起動する。
強制交代候補が2つあっても、予算が2倍にはならない。

`advice[].status.search.terminal_search`に以下を保存する。

- `particle_id`: 使用した仮説世界と観測の識別子。
- `simulations` / `terminal`: 完了した試行数と実際の終局数。初回rootの終局も`terminal`に含む。
- `censored`: 120ターン上限でV_refを使った試行数。
- `unfinished_at_deadline`: 最終時刻に未完了で、採点しなかった試行数。
- `failed` / `errors`: シミュレーターの実行失敗。勝敗には変換しない。
- `tree_nodes` / `max_tree_decisions`: 実際に選び直しの対象にした木の規模・判断数。
- `max_rollout_turns`: 終局試行で進めた最大ターン数。木の深さとは別の量。
- `immediate_wins` / `certificate_scope`: 即勝ちの確認結果と範囲。

`root_evidence`には手別の期待値・最悪値・試行数を残す。
時間によって完了試行数は変わるため、同じ型候補でも推定値が完全に一定になる保証はない。
本件のような終局手の取り逃しは、繰り返し実行する回帰検証で監視する。

ローカル検証:

```bash
uv run pytest -q tests/test_terminal_search.py tests/test_planner.py
uv run python scripts/ladder.py --local --local-opponent heuristic --battles 2 \
  --planner on --value-run runs/terminal-value-v2 \
  --out data/processed/diagnostics/terminal-search-local
```

旧固定深さの価値探索との診断比較に限り、`--search '{"terminalSearch":false}'`で旧経路を使える。
公式ラダーの再開は、取り逃しの回帰・時間上限・ローカル接続を確認してから行う。
実戦で探索のfallback・実行失敗・10秒超過が出た場合は、その対戦の終了後にexit 78で停止する。
`collect.sh`もSTOPを作り、次の対戦を自動起動しない。未完了試行が1つ残ること自体は停止理由にしない。

## 2026-10-16の検証

問題の14ターン目を10回再計算し、全てムーンフォース。同一観測の仮説世界も一致した。
ほか4局面を含む14回で、応答7.91〜7.97秒、実際の終局713〜3,487件、120ターン打切り・実行失敗・fallbackは0。
ローカルの対戦2戦は1勝1敗、41判断の最大8.03秒、実行失敗・fallbackは0。
2戦目では120ターン上限による途中評価が3件あり、終局の証明とは区別している。
回帰141件に、時間境界での試行中断1件・運用の品質停止2件を追加して成功した。

これらは取り逃し修正と接続・時間制約の検証であり、勝率向上を証明する結果ではない。
集約結果は[検証JSON](audits/20261016-terminal-search.json)に記録する。
