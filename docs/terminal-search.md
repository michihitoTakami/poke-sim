# 時間制限付きの戦術探索と技の評価

`--planner on --value-run runs/terminal-value-v2` は1判断8.5秒の情報集合を共有する木探索。
現行の `public-information-set-uct-v2` は既定8通常ターンで先読みを打ち切り、
未決着の盤面を参照価値と公開盤面の比較値で評価する。途中で決着すれば実際の勝敗を使う。
API・ラダーとも同じAdvisorを使う。

以前のv1は各試行を最大120ターンまで参照方策で進めていた。
数手の木探索後は簡易方策に任せるため、終局試行の多さは全応答の読み切りや勝率の保証にならない。
また、途中評価を最初の終局試行で捨てる実装により、少数の勝ちで評価が+1へ跳ねる問題があった。
[10/16の評価調整](audits/20261016-search-evaluation.md)でv2へ変更した。

## 手の比較

1. 同じ公開観測では同じseedで相手の型の仮説を生成する。相手の実際の隠れた型や未来のログを補完しない。
2. 全仮説・全合法応答で効果を得られない自分の手をroot候補から除外する。
   満タンで被弾前に使う回復、能力変化の上限からの積み、交代先にも無効な技等が対象。
   後攻の回復、同速、先制技、積む前の能力低下、交代先に通る技、メガ進化自体の効果は残す。
   毒等による間近の決着を待つ手や、他に合法な手がない場合も考慮する。
   エンジンの合法手は変更せず、探索用の共通候補だけを絞る。
3. 相手が最後の1体なら攻撃による即勝ちを先に確認する。
   各仮説・全合法応答・エンジンの離散乱数分岐を列挙できた場合だけ確認済みとする。
   予算超過、列挙上限、未対応の乱数、まもる等の逃げ道は確認成功としない。
   未公開の全ての型への証明ではない。
4. 残る全root手×相手の全合法応答をまず1回ずつ試し、次の通常の技選択盤面を評価する。
   積み・回復・状態異常・交代を含む相手の合法応答は削除しない。
   次に各応答2試行を目標に配分してから、有望な手を追加探索する。
5. 後続も同じ観測を共有するUCT木から選ぶ。1試行で新しい枝を開いた後は公開方策で継続し、
   既定8ターンで未決着なら途中評価する。時間境界で停止した試行はgeneratorで続きから進め、
   最終期限に未完了の1試行は採点しない。
6. 実際の終局は勝ち+1・負け-1・引き分け0。未決着は
   `0.5 × (2 V_ref - 1) + 0.5 × 公開盤面評価` を±0.85以内に収める。
   盤面評価は残数・HP・状態異常・逓減する能力上昇から作り、未登場の相手を瀕死扱いしない。
   これは比較用の効用で、校正済み勝率ではない。
7. rootの途中評価を4試行分の基準として保持し、後続試行との加重平均を取る。
   開いた盤面の評価を1回の参照方策での勝ちだけで置き換えない。
8. 相手の型をまたいで1つの判断を選び、予測と最悪応答への備え `rho=0.3` を使う。
   決定的に1手を使う場合は、その手の期待評価と最悪評価から比較する。
   近い推定値には試行のばらつきから0.02〜0.10の効用の許容幅を設定し、その範囲で直後の1ターンの
   残数・HPの改善を優先し、さらに同程度なら先読み中の早い決着を優先する（`rootProgress: true`）。
   積みの能力上昇へ独立した加点は付けない。回復によるHP改善も対象であり、変化技の一律禁止ではない。
   速さは合法応答を均等に比較する第2目的で、相手の予測がまもるに集中しても攻撃の決着機会を消さない。
   この幅は真の勝率の誤差幅ではなく、独立でない試行に対する調整値。
   終局の確認結果は途中評価より優先し、木探索以外の厳密な行列比較にはこの幅を適用しない。

2026-10-18の修正理由・選出強化と検証結果は[積み判断と選出の改善](audits/20261018-selection-tactics.md)を参照。
`--search '{"rootProgress": false}'`で従来の決着速度だけによる比較を再現できる。
新設定は較正コンテキストにも含まれ、旧設定の勝率較正を流用しない。

公開継続方策は `public-baton-v1`。学習時の `public-reference-v2` は凍結したままで、
v2のモデルは参照方策の予測としてだけ使用する。新しい探索や人間相手の勝率へ再学習したとは扱わない。
強制交代も全受け手を1つの照会に含め、1判断の予算を共有する。

## 評価の表示と記録

行動を採用する確率と、行動自体の評価値は別。
`advice[].evaluations` / APIの `advice.evaluations` に以下を保存する。

- `utility`: 期待評価と最悪評価を合わせた比較値。
- `expected` / `worst`: 予測応答に対する評価と最悪応答への評価。
- `gap`: 最大の比較値との差。許容幅内で決着を優先すると、推奨手が評価最大と異なることがある。
- `selected`: 推奨手。画面では★で示す。
- `sampling_error` / `trials`: 試行のばらつきの指標と件数。独立試行の信頼区間とはみなさない。
- `excluded` / `reasons`: 除外した手と理由。評価0を割り当てた手とは区別する。

操作画面・オーバーレイには技ごとの比較値を表示する。
未校正のPPO報酬換算値は勝率の百分率として表示しない。
真の勝率表示は使用条件に合う校正が存在する場合のみ。探索設定変更後に古い校正を流用しない。

`status.search.terminal_search` は仮説識別子、試行数、実終局数、打切り数、未完了数、
エラー、実際の木の深さ、先読み上限、途中評価の種類、候補除外を保存する。
`root_evidence` は手別の数値、`tie_margin` は今回使用した許容幅。
仮説・参照方策・盤面評価に誤りが残る可能性があり、全ゲームの完全解析を意味しない。

## 起動と検証

```bash
PLANNER=on EXTRA="--value-run runs/terminal-value-v2" \
  setsid nohup ./scripts/collect.sh > /dev/null 2>&1 < /dev/null &
```

`decisionMs` は100〜9000ms、既定8500ms。`maxTurns` は先読みの通常ターン上限、既定8。
例: `--search '{"decisionMs":8500,"maxTurns":8}'`。
1判断10秒以内を確認し、fallback・実行失敗・10秒超過があれば対戦終了後に品質停止する。
単に試行が途中で打ち切られたことや最終未完了が1件あることは、探索エラーとは区別する。

```bash
uv run python -m pytest -q tests/test_terminal_search.py tests/test_effective_actions.py tests/test_search_evaluation.py
uv run python scripts/ladder.py --local --local-opponent heuristic --battles 1 \
  --planner on --value-run runs/terminal-value-v2 --out /data/poke-sim/validation/search-evaluation
```

旧固定深さの価値探索との診断比較は `--search '{"terminalSearch":false}'`。
今回の戦術上限・途中評価・候補除外は通常の時間制限付き木探索が対象。
[今回の比較と検証](audits/20261016-search-evaluation.md)、
[v1導入時の検証JSON](audits/20261016-terminal-search.json)は別々に参照する。

## 2026-10-17 の拡張（探索工学）

113戦の照合で、探索自身の勝率推定が定数予測より悪く校正されていること（Brier 0.262 対 定数 0.243、評価0.8帯の実勝率47%）、
root予算の中央値66%が先頭候補に集中し代替手は（世界×応手）セルあたり約1試行しか評価されないこと、
V_refの事前値が1試行で捨てられることを確認した。以下はその対策で、すべて `--search` のJSONで上書きできる。

| 設定 | 既定（value run あり） | 意味 |
|---|---|---|
| `priorVisits` | 4 | セルのV_ref事前値を何試行分の重みで残すか。PR #22 の `prior_weight` と同じ値を共有する |
| `rolloutPolicies` | `{"p1":["expert"],"p2":["disrupt","tactical","expert"]}` | 試行ごとに回す継続方策。相手にも `expert` を混ぜて対称にする |
| `columnFloor` | 0.3 | 全セルの初回試行後、相手の応手を計画者の予測 `q` に比例して配分する際、一様に残す割合 |
| `workers` | `POKESIM_SEARCH_WORKERS`（既定4） | 同じ世界を別の乱数列で探索するNodeワーカー数。セル統計を合算する（`merge_replies`） |
| `stream` | なし | オフラインのオラクル用の乱数列番号。`particle_id` に入る |
| `policyNets` | なし | `{"opp": <json>, "ours": <json>}`。学習した公開方策（`services/sim-tools/policy_net.js`） |
| `rolloutMix` / `rolloutNetTurns` / `rolloutTemperature` / `puct` | 0.7(opp)・0.5(ours) / 6 / 1.0・0.5 / 1.5 | ネットをロールアウト（展開後の最初のmターン）と木の事前分布（PUCT）に使う割合 |

応答には `stats`（セルごとの生統計）、`uncertainty`、`p2Prior`（相手ネットのroot応手確率）、
`summary.worker_simulations` / `workers_failed` / `predicted_columns` / `policy_nets` が加わる。

候補設定の優劣は実戦勝率ではなく、固定局面セットに対するオラクル後悔で判定する
（[局面セットとオラクル後悔](positions-oracle.md)）。

## 2026-10-18: 追加の思考時間を終局確認へ割り当てる

現行の実行設定は1手最大15秒。通常探索の8.5秒・8ターンを保ち、余剰時間を`terminalReview`へ使う。
同じ仮説と2乱数、3種類の公開情報方策で、合法手を最大120ターンまで比較する。
全比較が終局し、仮説×相手方策の各組で悪化せず、平均勝敗値が0.1以上改善する場合だけ手を変える。
即勝ち確認は優先し、比較が打ち切られた場合は通常探索の判断を維持する。
通知された残り時計が少ない場合には上限を短縮する。設定は`decisionMs`と`terminalReview`で変更できる。

単純な15秒化と12ターン化は、開発局面で終局比較が悪い手へ変わる場合があったため既定にしなかった。
この終局確認にも固定方策と仮説の偏りがあり、対人での正解を証明する機構ではない。
[公開構築と再学習の監査](audits/20261018-team-priors-refresh.md)に比較条件と制限を保存した。
