# バトン判断・素早さ推定の調査と修正

対象は `20261016-104000` より前の10/16の78戦。コード変更による勝率改善の測定ではなく、
判断経路の調査・再現・修正の検証。

## 確認した問題

- ペンドラー選出50・バトン26・瀕死37、ブラッキー選出57・バトン23・瀕死40、
  バトン役が正のランクを残して倒れた31回を再集計できた。
- バトンの使用宣言と実際の引き継ぎは別。集計では49宣言・37引き継ぎだった。
  通常交代でのランク消失は全ポケモンで26回、バトン役だけでは7回。
  連続まもるは「2回目以降の宣言」で20回、連続区間では10区間。
  ユーザーの集計と異なる項目はこの定義のまま残し、数値を合わせる補正はしていない。
  最後の1体でのまもる等も含むので、集計数をそのまま判断ミスの件数とはみなさない。
- 最新の終局探索は `public_policy.js`、従来の固定深さ探索は `lookahead.js` の expert を使用。
  後者だけ修正しても最新ラダーには届かない。
- 公開参照方策は、通常交代の判定がバトンより先。安全に積む・渡す計画と独立に交代していた。
- 受け手評価に渡す攻撃・防御ランクが反映されず、ブラッキーを安全な中継として評価する処理もなかった。
- 相手の型を観測済みの被ダメージ・行動順で更新する `belief` は実装済みだが既定で無効。
  最新ログも `belief:false`。さらに相手の変化技の行動順は一律に捨てていた。
- エンジンの `setStatus` は控えを対象にすると失敗するが、状態復元はこの呼び出しに依存していた。
  控えのまひ・やけど・どく・眠りが消え、交代後の素早さやダメージを誤る不具合を回帰テストで再現した。
  固定深さ方策の控えの素早さ見積もりも、おいかぜ・天候による加速を含めていなかった。
- 固定深さの planner では、混合戦略の最大確率の手を実行する経路が残っていた。
  個々の手の期待値・最悪値で1手を比較する処理は終局探索にしか適用されていなかった。
- 選出表には学習時の方策・対戦数等のメタデータがなく、実ラダーの低勝率が選出に戻っていなかった。

再集計: [78戦のJSON](20261016-baton-before.json)。

```sh
uv run python -m pokesim.evaluation.baton \
  --since 20261016 --until 20261016-104000 --out /tmp/baton-audit.json
```

## 実装

1. 公開情報から動く `public-baton-v1` を終局探索の継続方策・木の初期手に使用。
   もう1回積んでも安全に渡せるかを確認してから積む。危険時は持っている上昇を渡す。
   後攻で先に倒される場合は通常交代も選べる。先制攻撃も考慮する。
2. 安全なら防御+4、瞑想は特攻・特防+2を目安に積んで渡す。
   加速しないポケモンのまもる待ちと、直前にまもる／みきりを使った後の再使用を避ける。
   みがわりが音技・連続技・すりぬけを必ず防ぐとは扱わない。
3. 受け手ごとに、正負を含む引き継ぎ後のランクで火力・被ダメージ・素早さを評価する。
   安全に瞑想を加えられ、後ろに特殊の攻め手が残る場合はブラッキー中継も候補にする。
   ブラッキーから攻撃できないペンドラーへの往復は優先しない。
4. 固定深さ expert も、早めの引き継ぎ・ブラッキーの瞑想・受け手の評価を修正。
   planner は `--sample` 以外では、探索方式にかかわらず1手ごとの期待値・最悪値で比較する。
5. `belief` を Advisor／ラダーの既定で有効化。変化技も、エンジンが計算した実際の優先度が
   一致する場合に素早さの証拠とする。こうこうのしっぽ・あとだし・きんしのちから等による
   行動順を素早さの証拠にしない。ターン途中の素早さ・状態・場の変更も除外する。
   推定時間を判断予算に含める。ラダーでは `--no-belief` で旧運用との比較が可能。
6. ラダーの選出は同じ6体の直近200件の完了済み rated 対戦を参照。
   3体の組ごとの勝敗を、従来の対面評価12戦分を事前分布として縮約する。
   ローカル対戦・未終了・別チーム・同一対戦の重複を除外し、使用した履歴のハッシュを保存。
   Showdown の履歴を Switch 用APIの選出評価には混ぜない。
7. 実局面の再計算で、相手のさいきのいのりが要求する瀕死の対象を合法手から除外し、
   探索の一部が失敗する問題も発見。公開リクエストの `reviving` に従い、蘇生対象を選べるよう修正。
8. 控えは既存の状態異常として復元し、通常の状態初期化・明示的な眠り残りターン等を維持。
   交代時の猛毒カウンターのリセットは実エンジンに任せる。
   固定深さ方策の控えにも、おいかぜ・天候の素早さ補正を反映した。

学習用の `public-reference-v2` は保持する。固定深さの学習価値照会と既存の学習データ生成は
従来の参照方策を使用する。終局探索は新しい継続方策を使い、途中評価には引き続きv2のV_refを
補助として使う。`continuation_policy` と `bootstrap_reference` を別々に記録する。
新方策の価値として再学習済みとはみなさない。

## 検証

- 全326テスト成功（`uv run python -m pytest -q`）。変更したPythonファイルのRuff、
  JavaScriptの構文チェック、`git diff --check`も成功。
- 公開情報の方策と実エンジンを使い、危険時のバトン、空バトンの回避、瞑想後の中継、
  能力上昇に応じた受け手変更、連続まもる回避、致死的な先制技からの通常交代を検証。
- 素早さの推定は、スカーフ・まひ・おいかぜ・トリックルーム・メガ進化、同速、
  実優先度・強制後攻・ターン途中の変更を含むテストで検証。
- 「先制シャドーボールでシャンデラを倒せる」「ムーンフォースで倒せる」は、
  高すぎる途中評価を返すモデルを与えても実際の探索で攻撃することを検証。
  シャンデラの自己再生事故そのものに一致するログは見つからず、同条件を別途構成した。
- 6つの実局面を旧公開参照方策・推定無効／修正方策・推定有効で各1回再計算。
  入力は判断ターンまでのprefixとtrain限定の事前分布。未来の相手の型・技は使っていない。
  12照会は約7.85〜8.02秒、fallback・探索失敗は0。
  00:03終了対戦の2ターン目は回復からバトンへ変更、05:22終了対戦の14ターン目は
  引き続きムーンフォース。02:51終了対戦の10ターン目は連続まもるからてっぺきへ変更。
  これは候補手の変化の確認であり、引き継ぎ成功や勝率向上の証明ではない。
  例えば前者のブラッキーは相手のPawmotより遅く、相手が攻撃すれば先に倒されうる。
  行動順が正しく推定できても、不確実な相手行動下での選択の良否は別途評価が必要。
- ローカル対戦は1戦1勝。8判断、最大8.01秒、バトン1回、fallback・探索失敗・推定エラーは0。
  選出はブラッキー／ペンドラー／ボーマンダ。1戦を強さの評価には使わない。

[実局面の照会結果](20261016-baton-decisions.json)、[ローカル対戦の集約](20261016-baton-local.json)。

公開方策内の未公開相手の素早さ・ダメージは依然として概算。rootのシミュレーションは
観測で更新した型の候補とエンジンの実計算を使うが、6候補ですべての型を網羅する保証はない。
選出の縮約も、少数の対戦・旧方策の結果を使う実用的な補正であり、因果的な比較や校正済み勝率ではない。
運用後は同じ集計で、死亡前の引き継ぎ・ランク消失・空バトン・勝敗を確認する。
