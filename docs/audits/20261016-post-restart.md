これは修正前の調査記録。後続の[修正と検証](20261016-live-state-fixes.md)を参照。

対象は PR #20 マージ後の `b58f514f6bdba2e48e2c0fa9d6489f0ad82bd4ff`。
13:46 JST の再起動から14:02 JSTまでの公式ラダー7戦、保存された85判断を確認した。
集計とオフライン再現結果は [JSON](20261016-post-restart.json) に保存した。

## 最優先: 実際のバトン後、次の判断で引き継いだ状態が消える

これはログの再構築と保存済みの実探索情報の両方で確認した不具合。

| 対戦・次の判断 | 実際に引き継いだ状態 | Pythonの判断入力 |
| --- | --- | --- |
| `134836` T5 ボーマンダ | 素早さ+3 | 全ランク0 |
| `135307` T10 メガボーマンダ | 防御+6・素早さ+4・みがわり | 全ランク0、みがわりなし |
| `135816` T14 サーフゴー | 特攻+1・特防+1 | 全ランク0 |

ログprefixを `BattleSession` に入力した状態と、同じprefixをJavaScriptの
`PublicObservation` に入力した状態を比較した。後者は正しく引き継ぎを保持している。
さらに `135307` T10 の実際に保存された `root_speed_samples` は自分の素早さ142。
素早さ+4なら426なので、オフライン再構築だけに生じた問題ではない。

そのT10では、HP35/202のメガボーマンダが、上記の防御・素早さ・みがわりを持ったまま、
HP1のペンドラーへ通常交代。ペンドラーが倒され、再登場したボーマンダもT11で倒された。
通常交代を選んだことは確実で、入力の欠落も確実。ただし、入力を直した後の手の変化は未検証。

原因箇所:

- `poke_env.battle.Battle.switch()` は退出時に能力ランク等を消し、受け手にコピーしない。
- `src/pokesim/state/tracker.py` は技ロックのみを扱い、バトン引き継ぎを補完しない。
- オンラインの `AdvisorPlayer` は通常の `Battle` を生成する経路を継承している。
- `src/pokesim/search/lookahead.py` の `mon_state()` がその状態を探索の初期盤面に使う。
- シミュレーション内の未来のバトンと公開観測器では引き継げるが、現実の次ターンの
  探索入力が正しくない。前回の方策・シミュレーション内の検証では、この接続を見落とした。

修正案は、オンライン・録画再構築・beliefで共有するプロトコル処理にバトンの引き継ぎを実装すること。
成功したバトン交代で正負のランクと引き継ぎ対象の状態を保持し、普通の交代・強制交代等と区別する。
「実ログ受信→バトン交代→次の要求→探索初期盤面」の統合テストを追加する。
通常交代への罰則や積み回数の調整より先に、盤面の正しさを直す必要がある。

## 最優先: 終了後の判断要求が品質停止を引き起こす経路

保存された85判断にはfallback・判断例外・シミュレーション失敗がなく、最大時間も8.01秒。
一方でプロセスは `search fallback` で停止している。保存外の判断を疑って確認した。

最後の対戦のログを勝敗確定まで再構築し、通信を開始しない `AdvisorPlayer` で
終了済み盤面への `choose_move()` を呼び出すと、以下を再現できた。

1. `battle.finished=True` でも探索を開始する。
2. 終了コールバックで対戦ログが破棄済みのため、価値探索が
   `ValueError('learned search requires a value model and observed history')` になる。
3. `quality_issues` に `search fallback` が追加され、終了後に新しいadviceリストも作られる。
4. 終了済み対戦に対する `/choose move ...` を返す。この再現ではサーバーへ送っていない。

`scripts/ladder.py` の終了コールバックは `logs` / `advice` を取り除くが、
`choose_move` に終了ガードがない。依存ライブラリもInvalid choiceの再要求時に終了を判定しない。
今回の未保存fallbackそのものの要求・例外は記録されていないので、停止原因との同一性は未確定。
ただし、同じ停止理由を起こす不具合は再現済み。

修正案:

- 終了済み要求を探索前に破棄し、探索完了後にも要求が有効か確認する。
- 古い要求への選択を送らない。要求ID、対戦タグ、判断前後の状態、送信内容を保存する。
- 品質停止の原因を対戦終了後も別ファイルに残す。実対戦中のfallback停止は維持する。
- 終了後の未処理メッセージや処理タスクを整理してから終了する。

なお、PSClientのメッセージ処理には対戦ごとのロックがある。
同一対戦のメッセージが無制御に並行実行されている、とはこの調査では認めていない。

## 優先度高: 先制した証拠があっても、全候補が相手の方を速い

`135816` のサーフゴー対通常フラエッテ:

- T14: サーフゴーのわるだくみが先、フラエッテのめいそうが後。
- T15: ラスターカノンが先、ムーンフォースが後。相手HPを19%にする。
- T16: ラスターカノンで倒せる状況で自己再生。相手こうごうせいで69%まで戻る。
- T17: シャドーボールで23%にする。
- T18〜21: 自己再生4連続。T22のラスターカノンでようやく倒す。

T15〜16の実探索では、自分の素早さ136に対して6候補すべてが相手147〜237。
T18〜21では全候補が相手156。それ以前の実際の行動順と矛盾している。
この間にメガ進化・素早さランク・状態・場による逆転はなく、同速も説明にならない値。

beliefは有効で、行動順観測も取得していた。問題は候補の中に正しい遅い型がないこと。
現在の事前分布とT16までのprefixによる再現では、48候補中、T14・T15の行動順を
説明できる候補は0。性格・素早さ配分を変えた遅い合法候補なら説明できた。
当時の48候補全体は保存されていないため、これは完全に同じ事前分布の再現ではない。
一方、当時の実探索6候補がすべて速いという矛盾は、保存済みJSONで直接確認できる。

`src/pokesim/belief/sets.py` は有限の48候補を再重み付けし、尤度に下限0.02を置く。
すべての候補が観測に反している場合、再重み付けだけでは正しい型が現れない。

修正案は、観測と両立する候補が不足したら、素早さ配分・性格・アイテム等の合法候補を
追加して再評価すること。候補の観測整合率・全候補棄却を記録し、下限で正規化しただけの
分布を確かな推定として扱わない。同速や優先度による例外は引き続き区別する。
回復反復にはバトン由来の特攻・特防欠落も影響しうるので、両方の入力修正後に再評価する。
それぞれの不具合が手の選択に与えた寄与は、現段階では切り分けていない。

## 優先度高: 選択記録と実際に出た技の不一致を追跡する

`135040` のサーフゴーには次の不一致があった。

| ターン | 保存されたchosen | サーバーのmoveログ |
| --- | --- | --- |
| 7 | じこさいせい | わるだくみ |
| 9 | シャドーボール | じこさいせい |
| 11 | ラスターカノン | シャドーボール |
| 12 | じこさいせい | シャドーボール |
| 13 | シャドーボール | ラスターカノン |

同対戦T3のブラッキーは先手アンコールによる変更で説明できるため、上の5件とは分けた。
サーフゴーへのアンコールはおうごんのからだで無効とログに出ている。
他6戦には、実際に技を使った通常判断でこの種の不一致はなかった。

現状の記録は選択ラベルまでで、最終的な送信コマンド、要求ID、サーバー受理を保存していない。
このため、5件をそのまま探索の誤判断と認定することも、通信上の原因と断定することもできない。
ラベル→注文変換後のコマンドとrqidを記録し、再要求・重複要求・古い要求との対応を検証する。
送信選択と実行技を突き合わせる監査も必要。

## 方策を調整する前の検証順序

1. バトン後の実盤面復元と、終了済み・古い要求の扱いを直す。
2. 先制証拠と両立する型が候補に含まれるようにし、送信内容の追跡を追加する。
3. 上記の実ログを使い、ボーマンダの通常交代、サーフゴーの回復反復、
   ブラッキーの死亡前の引き継ぎを再計算する。実行技の変更と勝率改善は分けて測る。
4. なお残る問題について、回復・積みと確定撃破の比較、危険な中継、アンコール時の交代を調整する。

フラエッテの満タン時のこうごうせいを一律に禁止するのは適切ではない。
`140008` T3は相手のちょうのまいに対して回復が失敗したが、相手が先に攻撃すれば回復は成立する。
控えにてんねんラウドボーンもいた。結果だけで全回復をミス扱いせず、判断時の情報で比較する。

今回は調査と修正箇所の整理まで。品質停止を解除して対戦を再開する変更は行っていない。
