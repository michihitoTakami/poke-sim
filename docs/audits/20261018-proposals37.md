# PR #37 の残項目の実装

相手選出の推定だけを追加した #38 の続き。#37 の五つの提案を実装し、盤面・判断・選出・学習を接続した。
通常経路では盤面の修正、実行記録、HP補助評価の停止、許容幅の固定、3対3選出評価を使う。
計画・上位2手への集中探索は比較実行できる。学習候補は生成・学習・推論まで実行したが、未使用の較正群がないため採用条件を満たしていない。
実戦勝率の改善を確認したという報告ではない。

#37で調査済みの24戦は開発用に固定する。同じ対戦の別名コピーも訓練・較正へ入れず、全ターン・全候補・全世界を同じ分割へ置く。
未完了・失敗を負けラベルへ変換しない。行動順位の学習では未完了がある原局面を除外する。
価値は根の介入手を除き、固定した継続方策が実際に選んだ通常判断だけから学ぶ。

## 素早さと先後

既存の型事後分布は、同じ優先度の実行順から速度・性格・スカーフ等の候補を制約する。
各仮説での実際の行動順はエンジンが処理する。今回、根の各候補について最初の行動順を記録し、相手の応答予測で重み付けした
`acts_first` と仮説間の `acts_first_range` を返し、画面に「先に行動」を表示する。
先制技・同速・麻痺・トリックルームを含む行動順であり、未知の全型に対する確率や較正済みの確信度ではない。
交代が先に起きる場合も行動順に含む。仮説の支持が不足する状態は既存の `belief.speed_support` で確認する。

## 収集停止を再現して修正

収集は `2700182186` のT21で品質停止していた。メガフラエッテをコピーしたメタモンの能力値変化を、メガシンカと誤判定していた。
Transformを石なしのメガとして復元しようとして全ワーカーが失敗していた。

変身元・コピー時の姿・公開済みの技・既知の能力値を保存し、エンジンのTransformでコピーする。
元のHPと持ち物を保持し、コピー技の最大PPは5、使ったムーンフォースは残り4となる。
自分のメガ後の能力値は構築と現在の姿から再計算する。非公開の相手の能力値は仮説のままとし、変身した側のrequestに残る元の能力値をコピー後の確定値として扱わない。
変身終了時の公開状態も元に戻す。
停止局面の再実行で合法手を返し、探索失敗0・fallbackなしを確認した。

## 学習と採用

初回の分岐2,388対戦で行動順位と継続価値を学習した。
学習した行動順位を固定してもう一度2,388対戦を生成し、その方策の継続価値を更新した。
同じ原局面を使う二段階であり、4,776件の独立した対人対戦ではない。
生成したデータ、候補checkpoint、JSON方策はworktreeの無視対象ディレクトリに置く。入力・コード・モデルのhashと結果は隣の監査JSONに残す。

採用には、開発用と重複しない較正対戦20件以上、元対戦単位bootstrapによる行動順位regretの改善、
価値Brierの0.015以上の改善と90%区間の改善を要求する。較正群がない今回の候補は通常ロードで拒否される。
`allow_candidate=True` はオフライン推論検査専用。候補を明示的に指定しない通常運用は既存の価値モデルを使う。

## 実行方法

```bash
# 現在の観測コードと一致する、訓練限定priorを再生成
uv run python -m pokesim.data.prior_bundle --allow-empty --out data/processed/scoped/priors37.json
# 過去の原記録を変更せず、実選出・実行主体を付加したコピーを作る
uv run python scripts/migrate_record_provenance.py --records data/raw/ladder --out data/processed/provenance37
# 訂正・失敗局面の抽出と、根の全合法手の公開情報による終局比較
PYTHONHASHSEED=0 uv run python -m pokesim.learn.branches generate \
  --priors data/processed/scoped/priors37.json --out data/processed/branches37 \
  --limit 16 --worlds 2 --seeds 2 --max-turns 160
uv run python -m pokesim.learn.branches train --data data/processed/branches37 \
  --out runs/branch37-rank --init-value runs/value-replays-v1 --epochs 24
# 学習済み方策を固定し、その方策用の価値を更新
PYTHONHASHSEED=0 uv run python -m pokesim.learn.branches generate \
  --priors data/processed/scoped/priors37.json --out data/processed/branches37-policy \
  --limit 16 --worlds 2 --seeds 2 --max-turns 160 --continuation-net runs/branch37-rank/ours.json
uv run python -m pokesim.learn.branches train --data data/processed/branches37-policy \
  --out runs/branch37-value --fixed-policy runs/branch37-rank/ours.json \
  --init-value runs/value-replays-v1 --epochs 24
# HP補助・許容幅・集中探索・計画の固定世界比較（開発用）
uv run python scripts/eval_proposals37.py --priors data/processed/scoped/priors37.json \
  --value-run runs/value-replays-v1 --out data/processed/eval37
```

`generate --positions` は `{file, turn, split, actions?}` の配列を受ける。
`calibration` も明示指定できるが、調査済み24戦・訓練・開発との重複は禁止する。
初期priorに開発・較正対戦を混ぜない。較正はepoch選択後に一度だけ採点する。

計画と集中探索の比較実行は、ラダーの `--search` に以下を渡す。

```json
{"focusTopTwo":true,"rolloutPolicies":{"p1":["planned"],"p2":["disrupt","tactical","expert"]}}
```

どの手も一律に加点・禁止しない。0.005の厳しい許容幅等は `scripts/eval_proposals37.py` で比較する。
通常の選出評価は最大48対戦を追加するため、見せ合いで従来より計算時間を要する。
失敗時は根拠を記録して静的順位に戻り、未完了は結果の上下限として表示する。

`--control-mode autonomous_ai` は人の選択で上書きされない運用に限り明示する。
既定は `unknown`。AIが送信したという記録だけで、同じ技を押した人の関与まで否定しない。
対戦サポートでは選出のユーザー確認と、`POST /api/execution-source` の `{turn, action, source}` 宣言を保存できる。

## 検証の読み方

固定6局面の仮説は、当時の観測prefixと訓練priorから作った型であり、実戦の真の型ではない。
身代わりを選ばなかった局面がすべて直った、急所型を常に見破れる、バトンが必ず成功する、という実証ではない。
有限時間探索の手は実行速度・乱数で変わり、終局比較も継続方策に依存する。計画と集中探索は一様な改善が出ていないため通常設定にはしない。

ローカルの通し対戦1勝、8判断、探索失敗・ランダム代替0件。選出の48対戦もすべて終局した。
対人の勝率改善を判定するには、実際の選出・操作主体と版を記録した新しい前向き比較が必要である。
