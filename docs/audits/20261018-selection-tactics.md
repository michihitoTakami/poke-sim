# 2026-10-18 積み判断と選出の改善

前回の追加学習で採用を見送ったNNモデルは維持し、実際に選ぶ処理を修正した。
対象は00:44:04までの保存済み131戦（61勝70敗）。103戦でサーフゴー・フラエッテ・ラウドボーンを選出していた。
比較元はPR #35を含む`5f7b33c`。原本・実装のSHA256と比較結果は[検証JSON](20261018-selection-tactics.json)、
調べた判断の一覧は[局面リスト](20261018-selection-tactical-cases.json)に保存した。

確認した問題は次の2点。

- **攻撃より低い比較値の積みでも、先読み中の決着が速いと採用される。** 木探索の比較では、
  不確実性に応じて0.02〜0.10以内の効用差を同程度とみなし、その中で決着速度を優先する。
  この速度は将来の簡易方策での勝ちから得ており、今の相手を倒す手より積みのほうが高くなる場合があった。
  例として22:51:59の初手はシャドーボールの比較値0.546に対し悪だくみ0.463を選んでいた。
  評価の差と、その後負けたという結果だけでは「攻撃すれば実戦で必ず勝てた」とは断定しない。
- **相手に応じた選出補正が先発だけに結び付いている。** 従来の`PreviewLogistic`は
  自分の先発と相手6体の種族の相関だけを学ぶため、同じ先発でも控え2体を入れ替えた相性の違いを学べなかった。
  復旧前の成績も事前分布として残っており、まだ試していない3体には相手6体に対する具体的な評価が足りなかった。

技選択では、各root手×相手応答の**最初の通常ターンが完了したときの盤面変化**を別に記録する。
残数1体を0.7、合計HP割合を0.35とする既存の盤面評価と同じ重みを使い、能力上昇そのものには加点しない。
途中の強制交代まで進めた結果を採点し、未完了試行を勝ちに数えない。
この情報を許容幅内の第2目的にし、決着速度はさらに小さい第3目的とする。
主目的で明確に高い積みは残し、回復が有効なら回復も選べる。即勝ち確認の優先順位は維持する。
複数ワーカーの試行は件数で合算し、rootの事前評価は1回分に統合する。

選出では以下を加えた。

1. **控えを含む3体の学習。** 先発×相手の相関に加え、自分の各メンバー×相手6体の相関も正則化して学習する。
   モデルは選出時点までの完了済みレート対戦を使って再構築される。
2. **未経験の選出にも相性の比較値を用意する。** 自分の実際の6体の型と、公開された型事前分布からの
   相手の仮説を使い、与ダメージ・被ダメージ・行動速度をシミュレータで静的に比較する。
   相手各ポケモンへの最良の受け答え、最も苦手な相手、先発相性を60候補ごとに集約する。
   重みは平均相性0.6、最悪相性0.4、先発相性0.25であり、学習済みの勝率ではない。
3. **メガシンカの競合。** フラエッテとボーマンダが両方いる場合も、1体ずつのメガ配分を比較する。
   両方が同時にメガできる前提では採点しない。タイプ変化、吸収特性、天候の候補も静的比較に含める。
   非攻撃役が1発を耐えるだけで、その相手への攻撃役として数えない。
4. **データと運用。** 保存選出と実際の出場が異なる1戦を選出学習からも除外。
   型仮説生成の乱数は対戦探索へ影響しないよう戻す。相性の静的計算に失敗した場合も、従来の履歴に基づく選出を返す。
   ラダーと対戦サポートAPIは同じ候補順位を使い、画面では未較正の値を「相性評価」として表示する。

ここでの3体相性はサンプルした型での静的比較であり、交代・積み・設置技を含む完全な選出探索ではない。
公開されていない相手の正しい型や選出を、後のログから入力へ戻すことはしていない。
型データと少数対戦での学習に誤差が残るため、経験の浅い組み合わせが常に強いと判断するものではない。

8つの実戦局面は、そのターンまでの観測だけを再構成して、同じ探索行列から旧新の判断を比較した。
探索予算4.5秒・2ワーカー、実測約3.81〜3.85秒、試行失敗0。
5局面で判断が変わり、4局面は積みから攻撃、1局面は悪だくみから回復へ変わった。

計120試行の82勝38敗→96勝24敗。
各局面の最初の3仮説×4乱数列×`expert/tactical`・`expert/disrupt`、最大100ターンで比較した。
これは同じ仮説での継続評価であり、継続方策は仮説の完全な盤面を参照する。
実際の人間相手で96勝できるという意味ではなく、隠れた真の型への勝利証明でもない。

選出は整合する130戦のうち直近40件を古い順に評価し、各件より前の履歴だけでモデルを作った。
控え込みの学習モデル単体で、実際に出した選出のBrierは0.25721→0.24990。
これは過去の選出の勝敗予測の比較であり、別の選出を出した効果を表す数字ではない。

相性補正込みでは40件中6件で選出が変わり、うち3件で3体の組み合わせが変わった。
変更された6件を、同じ相手の仮説3選出×3乱数列×`expert/expert`・`expert/disrupt`で比較した結果は以下。

|---|---:|---:|
| 模擬対戦の勝ち | 57/108 | 81/108 |
| 負け | 51 | 27 |
| 引分・未完了・失敗 | 0 | 0 |

23:31:22の見せ合いでは、特殊3体からボーマンダ・サーフゴー・ブラッキーへ変わり8/18→18/18。
一方00:23:26ではフラエッテをボーマンダに入れ替えた結果が7/18→4/18となった。
この退行も記録し、合計の改善だけで「全ての選出が改善した」とは扱わない。
6件は独立な108試合ではなく同じ仮説・継続方策の反復を含み、実戦勝率の有意な改善は未検証。

再実行用コマンド。Nodeエンジン・図鑑・型事前分布・復旧時のモデルと対戦原本が必要。
時間制限付き探索の配分により、再実行時に同程度の候補や試行数が変わることがある。

```bash
uv run python scripts/eval_selection_tactics.py \
  --baseline-ref 5f7b33c --until 20261018-004404 --simulate \
  --out data/processed/selection-tactical-recheck
```

`--mode preview` / `--mode moves`で分けて実行できる。実行はオフラインで、Showdownへの対戦注文は送らない。
ラダーの相性補正だけを外す場合は`--no-preview-coverage`、技選択の旧比較は
`--search '{"rootProgress": false}'`。旧版全体の比較には上記のbaseline refを使う。
新しい比較設定は較正コンテキストに含まれる。

実戦収集の作業ツリーには手を加えず、専用worktreeで実装・検証した。NNモデルの重みも上書きしていない。
コードの本番適用後は、新たな完了済み対戦で判断・選出・停止率を追跡する。
関連157テスト、ruff、Node構文チェック、`git diff --check`を通過。
