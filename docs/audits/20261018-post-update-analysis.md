# 2026-10-18 更新後の対戦履歴と次の改善

PR #36適用後も、積み・回復・攻撃・交代を数ターンの勝ち筋として比較する部分が弱い。
身代わりの過小評価と、探索へ渡す盤面の欠落を先に解消し、その上で選出と方策を終局結果で学び直すことを提案する。
このPRは分析資料とオフライン診断だけを追加する。対戦処理・モデルの変更や、新モデルの採用は含まない。

## 対象と解釈

保存時刻2026-10-18 02:18:38 JSTまでの166件を固定した。
`started`は現行の保存処理では試合終了時に付くため、以下の時刻は開始時刻ではなく保存時刻である。
各ファイルのSHA256、集計、判断の証拠は[監査JSON](20261018-post-update-analysis.json)に保存した。

新設定はコミット名だけでなく、`rootProgress=true`と`preview-coverage-v1`が記録されていることを確認した。
01:13:51の1勝はコミット名だけ新しく、両設定がない移行中の試合なので新設定群から外した。

**ユーザーによる選出・技の手動操作が含まれる。これらはAI単独の戦績ではない。**
`advice[].chosen`はAIの提案、`log`は実行された出来事として分けて読む。
両者の不一致を送信・実行の不具合と解釈しない。提案と同じ技が実行されても、操作主体までは確定できない。
行動する前に倒れた場合は技がログに出ないため、「技がない」ことを手動訂正の証拠にしない。
02:18:38以後の収集中の試合はこの集計に追加しない。

相手は14人で、10勝のうち5勝は同じ相手との対戦。それ以外は5勝14敗だった。
選出・対戦相手・手動介入が変わっており、前後差から改善・悪化の因果は判定できない。
前回の仮説世界での分岐対戦成績も、今回の対人勝率改善を保証するものではない。

## 相手と選出の傾向

相手が実際に場に出したポケモンごとの試合結果は、スターミーが0勝4敗、ブリジュラスが1勝4敗、
アシレーヌが1勝3敗。スターミーの4敗中3敗は同じ相手であり、種族だけの一般的な弱点とは断定しない。
技別では、きあいだめ・アクアブレイクを見た試合がそれぞれ0勝3敗、アクアジェットも0勝3敗だった。
技の登場と敗北の相関であり、技自体が必ず敗因だったという集計ではない。

AIが提案した3体は、サーフゴー・フラエッテ・ラウドボーンが更新前94/108戦から更新後9/24戦へ減り、
フラエッテ・ラウドボーン・ブラッキーが10/24戦へ増えた。選出候補の多様化は起きている。
ただし後者は提案に紐付く結果が5勝5敗で、ブラッキーによる特殊対策が物理型スターミーや急所型ブリジュラスへの
対策にもなっているとはいえない。提案選出と実際の選出は同一と仮定しない。

現行の相性評価は、相手ごとにこちらの最良の1体を選び、それらを合算する静的近似である。
その1体が消耗した後、別の相手を引き続き受けられるか、ステルスロックを踏んで何回交代できるか、
誰を通して勝つかは直接評価していない。`uncovered=[]`も安全な選出の保証にならない。

## 身代わりであくびを防ぐ価値

ユーザーの「相手があくびしてきそうなら身代わり」という指摘は、今回優先して取り込むべき課題である。
更新後の通常判断308件のうち、評価候補に身代わりがあった105件でAIが身代わりを選んだ回数は0回だった。
更新前の直近24戦では110件中4回。局面・選出が異なるため、この差だけでPR #36の因果は判定しない。

02:11:12保存の勝ち試合（`2700085386`）では、フラエッテ対カバルドンで次が起きた。

- T2・T3はムーンフォースに対してなまける。T4でもムーンフォースを提案・実行した。
- T4にあくびを受け、T5にカバルドンを倒すと同時に眠り、T6に後続ボーマンダのすてみタックルで倒れた。
- T4のAI比較値はムーンフォース0.063、身代わり−0.286。あくび予測は上位表示で8.2%だった。

試合全体は勝っているが、攻撃を連打してフラエッテを眠らせた経路は改善対象になる。
ただし地震は既に約51ダメージを出しており、HP173の身代わり43は地震で壊れる。
「カバルドン相手なら常に身代わり」ではなく、相手が回復・あくびを選ぶ可能性と、
身代わりを残した後の瞑想・回復・攻撃開始までを比較する必要がある。
この試合で身代わりなら必ず勝ちやすかった、という反実仮想の実証はまだ行っていない。

現行の第2目的`rootProgress`は最初のターンの残数と本体HPを測る。
身代わりで防いだあくび、残った身代わりHP、次の積みの安全性を直接加点しないため、
本体HPを43失うだけなら約0.087の不利が付く。一方、回復は本体HPの増加として加点される。
これは主評価が近い候補の順位を変え得る。ただし上のT4の身代わりは主評価で0.349下がっており、
許容幅0.1の外にあるため、**補助評価の修正だけではこの判断は直らない**。

また、あくびを受けた後の身代わりは既に付いた眠気を消す対策ではない。
「あくび前に先手で張る」「既に眠気があるので交代等を比べる」を別の判断として扱う。

## 探索へ渡す盤面の欠落をローカルで確認

[診断スクリプト](20261018-post-update-state-probe.js)は通信せず、仮説の型で盤面復元と1ターンの結果を比較する。
出力は監査JSONの`state_probes`に収録した。実戦の真の型を復元した試験ではなく、欠けた状態の影響を切り分ける診断である。

1. **あくびの残り時間が延びる。** `mon_state`は効果名を渡すが、残り時間を渡さない。
   `setUp`で新しいあくびを付けると残り2となり、次のターンを終えても残り1で起きたままになる。
   実戦で残り1の状態なら、そのターン末に眠る。残り1を明示した対照では正しく眠った。
   02:13:33のT5のような眠気を受けた後の回復・居座りを、余分な1ターンがある盤面で評価し得る。
2. **そうだいしょうの回数が欠ける。** 倒れたポケモンはHP0として復元するが、
   `side.totalFainted`と発動中の`abilityState.fallen`は復元しない。診断では控え2体が倒れていても両方0/未設定だった。
   復活を含む実戦の公開値`fallen3`は、現在倒れている2体を数えるだけでも復元できない。
   同じ仮説盤面・乱数・行動で、回数なしでは被弾後HP107、3回を明示するとHP63となった。
3. **身代わりによるあくび防御自体は動く。** HP92/173のメガフラエッテが先に身代わりを置く仮説対面では、
   身代わりHP43が残り、あくびは失敗した。技そのものが未実装という問題ではない。

診断の再実行（リポジトリのエンジンとチームファイルが必要）:

## 改善の優先順位と実験

1. **盤面復元と操作主体の記録を整える。** あくびの残り時間、公開されたそうだいしょう回数を引き継ぎ、
   同じ公開盤面からの次の1ターンが実戦の処理と一致する回帰例を追加する。
   提案と実行を別のフィールドにし、実際の選出3体はサーバーの自分側requestから保存する。
   手動・AI・不明の出所も保存し、不一致を理由に手動対戦全体を学習から捨てる運用を減らす。
   確認できない過去の操作主体は推測で埋めない。
   現行でも行動教師は実行ログから抽出しているが、操作主体の区別がなく、選出不一致は試合全体を除外している。
   既存の手動試合は自分の3体を確定できる範囲で実際の選出を別に復元し、相手の未来の公開情報は判断へ混ぜない。
2. **その場のHPを優先する補助評価を見直す。** 現行、通常判断308件中298件で許容幅が上限0.1になっている。
   広い許容幅内で本体HPだけを比べると、身代わり・安全な交代・将来の妨害回避を落とし得る。
   固定した同じ局面で`rootProgress`の有無、許容幅の変更、候補2手に絞った追加探索を比較する。
   攻撃・回復・身代わりのどれかへの一律ボーナスや禁止ではなく、採用した手の終局成績を採点する。
3. **1手でなく計画を学ぶ。** 「あくび/回復を読んで身代わり→瞑想→攻撃」
   「必要な素早さを得たら受け先へバトン」「急所型判明時は特殊耐久積みの計画を再評価」を比較候補にする。
   開始条件・達成目標・中断条件を持たせ、新しい技や型が判明したら選び直す。
   ユーザーの指摘を、身代わりが残る対照例・攻撃で壊れる例・既に眠気が付いている例に分けて検証する。
4. **選出を3体の継続対戦で評価する。** 既存の静的相性は60候補の絞り込みに使い、
   上位候補を相手の選出3体・型・先発の複数仮説と対戦させる。メガ枠・設置技・交代の消耗・受け先の競合を含める。
   初手だけの候補変更に終わらせず、スターミー＋ブリジュラスのような並びに誰を残して勝つかを比較する。
5. **手動訂正と失敗局面を、終局まで分岐する学習へつなぐ。** 既存の`branch_matches.js`には
   `informationScope=public_observation`がある。これを使い、同じ観測から攻撃・身代わり・積み・回復・交代・バトンの
   有力候補を比較する。隠れた真の型を見ない継続方策を使い、結果で行動の順位を学習し、実際の方策に合う価値を更新する。
   生の勝敗を全ターンの手の正誤へ変換せず、手動の1手とAIの続きを組み合わせた結果も分ける。
   同じ原局面の全枝は同じデータ分割へ置き、調査済みの今回の24戦は開発用とする。

最初の実装単位は1と、身代わり・急所・バトンの固定局面集を作ること。その後2・3を終局成績で比較し、
4・5へ接続する。探索時間を単に増やしても、あくびが1ターン遅れる仮説や、受け先が消耗しない静的近似は直らない。
現構築の使用法の改善を主実験とし、構築変更は必要性を切り分ける追加実験に留める。
