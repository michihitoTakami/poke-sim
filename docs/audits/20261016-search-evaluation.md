# 探索値の過大評価・技の比較・無駄手の調整

## 調査

旧探索は「全分岐を終局まで読み切る」方式ではない。
最大120ターンの試行を行うが、木で数手を選んだ後は簡易な公開参照方策に任せる。
その方策に勝てることを、人間に対する勝ちの保証とみなせない。
加えて、初回の途中評価を最初の終局試行で捨て、+1/-1だけに置き換える経路があった。

10/16 22:00より前に保存された `db80f64` の公式対戦112戦では、初回判断のPPO換算値は平均0.721、
結果は50勝62敗（44.6%）。PPOの値は勝敗以外の報酬も含むため、元々真の勝率ではない。
これは2種類の方策・複数対戦相手・降参等を含む記述統計で、校正や改善効果の測定には使わない。

APIの技の棒グラフも技の評価値ではなく採用確率だった。
決定的な選択では採用手100%、他0%となり、期待値・最悪値・差分が見えなかった。
一方、エンジンの合法手をそのまま候補にしていたため、失敗する回復・上限からの積み・無効技も残っていた。

## 変更

- `public-information-set-uct-v2` は既定8通常ターンの戦術探索にする。
  未決着時は凍結したV_refと公開盤面（残数・HP・状態・逓減する能力上昇）を半分ずつ使い、
  ±0.85以内の比較値にする。未登場の相手は健康な残りの選出個体として扱う。
  実終局の±1と、確認済みの即勝ちの優先は維持する。
- 初回の途中評価を4試行分保持し、最初の深い試行だけで評価を置き換えない。
  全応答に2試行ずつを目標としてから追加配分する。
- 比較値の僅かな差を過信せず、ばらつきから決める0.02〜0.10の範囲で早い決着を優先する。
  これは真の勝率の許容損失や厳密な信頼区間ではない。範囲外の明確な差は維持する。
  相手予測がまもるだけに集中しても、他の合法応答に即勝ちする攻撃の決着機会を消さない。
- 全仮説・全合法応答に対して効果がないrootの技を除外し、理由も記録する。
  満タンで先に回復する手、上限の積み、タイプ・特性・状態異常の無効が対象。
  後攻の回復、先制技、同速、トリックルーム、先に能力を下げられる場合、交代先に通る技、
  メガ進化の有効性、かたやぶり・きもったま・ふしょく等の例外を検証する。
  残りの合法手を全て消さず、毒等による間近の決着を待つ手も1つ残す。
- 操作画面とオーバーレイに比較値を出す。採用確率とは分け、期待値・最悪値・最大との差・
  推奨手・除外理由をAPIとログにも保存する。未校正のPPO値を百分率で示さない。
- モデルの特徴量・重み・学習用の参照方策は変更しない。新しい設定では旧設定の勝率校正を流用しない。

## 固定した仮説での比較

同じ観測prefix・同じ6個の相手仮説・同じ8.5秒予算で、masterと修正版を各1回照会した。
相手仮説は現在の事前分布から生成したもので、当時の仮説を再現したものではない。
未来のログは入力していない。数値は勝率でなく比較用の探索値であり、改善した勝率とは解釈しない。
[記述統計と照会結果JSON](20261016-search-evaluation.json)。
比較に使った[観測prefixと6仮説](20261016-search-evaluation-inputs.json)も固定している。

## 検証

- 既存の終盤ムーンフォース、先制シャドーボール、先制技、まもる・タスキ・命中・乱数列挙の回帰を維持。
- 後攻なら満タン回復を残す、先に被弾しないなら除外する、同速・先制技・トリックルーム等を追加検証。
  満タンのはねやすめは実エンジンの失敗とタイプ変更がないことを確認。穴を掘るの回避効果等は残す。
- 上限からの積みを除外しつつ、先手のバークアウト・くろいきり・威嚇交代後の積み直しは残す。
- 無効技を除外しつつ、交代先に当たる技、かたやぶり、きもったま、ふしょくを残す。
  おうごんのからだ・火傷無効・毒無効・電磁波無効・粉無効も検証。
- モデルが0.99でも対等な未決着盤面の比較値は0.49。未登場の相手を無視して有利とみなさない。
  相手HP・残数の変化で差が出ること、+6以降の上昇を評価しないこと、1回の勝ちで基準を捨てないことを検証。
- APIの評価値と採用確率の分離、推奨手の表示、オーバーレイの数値表示を検証。
- 固定深さ・従来経路にも技の数値評価を公開し、採用確率の棒と区別する。
- 既知の終盤ムーンフォースを5回再照会し、混合・決定的な比較の両方で5回ともムーンフォース。
- 通常設定のローカル対戦1戦は、heuristic相手に8判断、最大8.05秒。
  fallback・探索失敗・注文と実行の不一致は0。強さの評価としては用いない。
- 最終版で `python -m pytest -q` は全395件成功（66.78秒）。変更PythonのRuff、
  JavaScriptとHTML内スクリプトの構文、`git diff --check` も成功。

公式収集を動かしているmasterは変更せず、別worktreeで実装・検証した。
