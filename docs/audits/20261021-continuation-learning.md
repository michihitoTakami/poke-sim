# 候補手比較からの方策学習と、固定した方策の価値学習

実装・学習・採用評価まで実行した。新しい重みは採用しない。
開発用の予測精度は改善したが、グループを分けた採用評価で優位を確認できず、
方策そのものの模擬比較も参照方策を下回った。
本番は既存の`runs/value-replays-v1`と`runs/opp-replays-v1/opp-seed0.json`、
15秒・4ワーカー、自軍6体を維持する。

## 実装した学習経路

新しい`learn.curriculum`は古い日付で固定された既存の自動抽出とは別に、締切と局面数を
明示して、最近の保存済み試合も扱える。2026-10-21 00:36:20を締切とし、
同じ相手・同じ見せ合いで連結したグループを分離した。既存分割を継承し、
矛盾する46試合を隔離した。名前の正規化後にも採用した試合の分割重複がないことを確認した。

選んだのは90グループ・90試合・179局面。学習50グループ100局面、開発20グループ40局面、
採用評価20グループ39局面である。全ての候補手・型・乱数・ターンを同じグループに固定する。
本人のリクエストは当該ターンの保存値から復元し、相手の非公開情報は使わない。
事前分布は公開構築のみ。後で判明した相手の技や最終勝敗を、手の教師に流用しない。

各局面は4つの異なる型状態・2乱数・4種類の相手方策で全候補手を比較した。
重複する型状態や乱数反復を独立した4世界として扱わない。
同じ相手方策で逆転されず、対応付き90%区間が正の行動差だけを順位教師にする。

まず参照方策のシミュレーション中の継続行動を800局面、10エポック蒸留し、
続いて40エポックの順位学習を行った。開発用の後悔量で25エポック目を選んだ。
学習した方策を固定して分岐を再生成し、現行価値NNを初期値として40エポック上限で価値を学習した。
開発用のlog lossで3エポック目を選び、その後に採用評価を実行した。

通常ターンだけを学習した方策が、バトン後や瀕死後の交代先も選んでしまう経路を修正した。
新しい方策に`decision_scope: move`を記録し、未学習の強制交代は参照方策へ任せる。
探索のprior、継続、終局レビューで同じ制限を守る。
継続価値を使う場合は、本人の固定方策と相手リーグの混合も探索へ接続する。
この契約がない従来の相手NNは、従来どおり全フェーズ対応として扱う。

## 評価の修正

固定方策を使った生成では、`policyRecommendation`も新方策の手になり、
それを基準にすると方策を自分自身と比較していた。
独立した`referenceRecommendation`を保存し、参照方策との比較を維持する。

価値の採用評価は、初期モデル1つとの比較から現行アンサンブル全seedの平均との比較へ直した。
初期乱数モデルだけに勝っても採用できない。
さらに、学習した方策そのものと参照方策の対応付き比較を要求する。
「弱くなった方策の敗戦を予測できた」ことだけで採用しない。
評価条件と手順は[学習手順](../continuation-learning.md)に記載した。

## 結果

参照方策と固定した学習済み方策について、37,408分岐ずつを生成した。
固定方策の価値用の通常判断は、学習58,661行、開発23,232行、採用評価22,572行。
これらは独立した10万試合ではなく、90試合から派生した相関の強い分岐・継続である。
全179局面で失敗・未完走は0。現在のコードで参照方策の採用評価39局面も再生成し、
8,288分岐で状態・型仮説・乱数・相手方策を学習済み方策と一致させた。

| 評価 | 結果 |
| --- | --- |
| 開発用Brier | 0.22055 → 0.15814 |
| 採用評価Brierの新−旧・90%区間 | −0.02355〜+0.03038 |
| 行動後悔量の新−参照・90%区間 | −0.02344〜+0.09609 |
| 方策比較のグループ平均得点 | 参照0.58203、学習済み0.50078 |
| 方策得点差の90%区間 | −0.15781〜+0.00082 |

方策の比較は39局面、各32対応試行、20独立グループで集計した。
新方策は平均で約0.0813下回り、採用条件の改善0.03・区間下限が正を満たさなかった。
採用評価を見た後に閾値を変更したり、このモデルを追加調整して同じ評価を繰り返したりしない。

悪化した比較には瞑想→バトン、攻撃→竜舞といった変更もある。
ただしこれはルート手と継続方策の両方を替えた比較であり、その一手だけに敗因を帰属させない。
局面の勝敗予測の改善と、長い勝ち筋を実行できることは別に確認する必要があった。

## 検証と反映

全633テスト、変更したPythonのRuff、Node構文、diff検査が成功。
独立した参照手、重複世界の排除、グループ単位の採用条件、候補の本番ロード拒否、
方策の適用範囲、バトン後の交代、終局を変えない軌跡の間引き、
継続・レビューの固定方策への接続を検査した。
不採用の実モデルが通常のロードでは拒否され、オフライン検証用の明示指定でのみ
有限の確率を出せることも確認した。
現行重みを使ったローカル1試合も、2.5秒・1ワーカーで完走し、フォールバック・探索失敗0を確認した。
これは更新した実行経路の検証であり、新モデルの勝率の証拠にはしない。

原記録と現行12モデルファイルは保全する。候補重み、分岐、分割、比較結果も保持する。
配備ではコードと最新の公開型集計を反映し、既存NNを継続して使用する。
型集計は914→1,074試合、実際に出た種族214→224へ更新する。旧ファイルを退避し、
既存カウントが減らないことを確認した。新しい分布でも保存した呪い局面の探索が正常に完走し、
通常交代を選び、フォールバック・シミュレーション失敗がないことを確認した。
今後の候補は新たに固定した評価データで調べる。今回の採用評価は将来の未見試験とは呼ばない。
