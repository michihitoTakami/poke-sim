# 選出と対戦判断を分け、候補手の終局結果を学ぶ

最高レート時の人間による操作を含む版を比較基準にしない。AIの提案と実行手の不一致を
誤りのラベルにせず、各合法手を実際にシミュレーションした終局結果から学習する。
現状はオフライン研究用で、本番Advisorには新しい出力を接続していない。

## 学習

`pokesim.learn.action_value`は既存の終局分岐成果物を検証して読み込む。
同じ相手・見せ合い構築のグループを分割間で共有せず、グループごとの重みを等しくする。
完走しなかった比較を負けと扱わず、固定した公開情報の参照方策の比較だけを使う。

既定の`--target advantage`は、各候補の終局勝率から同じ局面の全候補平均を差し引いて学ぶ。
局面全体の勝ちやすさに学習が偏るのを抑え、候補手による差に学習を向ける。
これは固定した仮説・継続方策に条件付けた優位度であり、最適方策のQ値ではない。
JSONの`score_transform: identity`は生の優位度で、勝率として解釈しない。
比較用の`--target return`はsigmoidと終局ラベルの交差エントロピーを使う。

3モデルの平均改善からモデル間のばらつきの1.64倍を差し引き、0.05を超えたときだけ
参照手を変更する。このガードはアンサンブルのヒューリスティックで、統計的な信頼区間ではない。
通常ターンのみを扱い、瀕死交代・バトン先の強制選択は参照方策を維持する。
開発データの条件付き後悔量でエポックを選び、その後に歴史的な校正用データを開く。

```sh
python -m pokesim.learn.action_value --data /frozen/experiment/planned \
  --out /new/action-advantage --target advantage
```

## 選出と判断の比較

`pokesim.evaluation.selection_decisions`は締切・コード版を固定し、相手または見せ合い6体が
共通する連結グループから1試合を選ぶ。勝敗を見て対象を選ばない。

選出比較は、AIが当時提案した選出を基準とする。全20組の3体と、静的な相性で絞った先発を
比較するため、全120順列を探索する実装ではない。探索用の型仮説で代替案を決め、別の
評価用仮説で「元の選出／代替選出」×「参照判断／新モデル判断」の4通りを比較する。
相手の3体は一様抽出であり、実際の選出傾向を再現した分布ではない。

対戦判断は保存された実際の選出・公開ログ・自分のリクエストを固定し、AIの提案と
全合法候補を同じ仮説・乱数・継続方策で比較する。人間が実行した手を正解にしない。
4型仮説×2乱数×4相手方策を用い、相手へ未来の型・技や非公開情報を渡さない。

```sh
python -m pokesim.evaluation.selection_decisions --records /data/raw/ladder \
  --commit COMMIT --before YYYYMMDD-HHMMSS --priors /published-only-priors.json \
  --model /new/action-advantage --out /new/selection-audit --groups 24 --worlds 4
```

`--reuse /old/audit`は探索で決めた選出と局面の比較を凍結して再利用する。
参照側の全試合を再実行し、保存済み結果と完全一致しない場合は停止する。
manifest、各試合、モデルのSHAを保存し、変更された成果物を継続に使わない。

これらの実行役は公開情報を使うスクリプト方策であり、本番の探索器ではない。
区間は元試合のグループを再標本化した記述的な90%区間で、将来の対人勝率を保証しない。
分析済みの履歴を新しい未見テストと呼ばず、改善しない候補を自動採用しない。
